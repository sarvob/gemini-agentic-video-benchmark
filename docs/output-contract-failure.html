When agentic video processing completes but the JSON contract fails

One Gemini 3.7 Flash agentic run completed and included a verified processing call, yet it was excluded because its returned text violated the benchmark’s frozen JSON-only contract. That is a reliability result, not a quality score.

What failed

The prompt required only valid JSON in an exact response shape and explicitly prohibited explanation outside the object. The returned text instead began with unstructured reasoning before a fenced JSON object. The frozen normalizer stopped at the first unexpected token and returned exit code 1.

Unexpected token 'h', "thought\nAt "... is not valid JSON

The public record stores the raw output’s SHA-256, the parse error, status, latency, token usage, and decision. The raw response itself remains in ignored local benchmark storage; no private URL, API credential, or personal information is published.

Why exclusion was the correct outcome

The v0.4 protocol was frozen before the request. It defined invalid JSON as an invalid run, allowed no repair call, and permitted the static arm only after a structurally valid agentic result. Extracting the fenced object, deleting the leading prose, or rerunning only the failed arm would have changed the acceptance rule after seeing the result.

Accordingly, quality metrics were not computed, the response was not repaired, the request was not retried, and the matching static arm did not run. The failure remains visible as one attrition among six frozen v0.4 fixture attempts.

What this teaches production evaluators

  • Completion is not validity. Provider status, tool execution, schema parsing, and task-level acceptance are separate gates.
  • Structure is part of reliability. A response that contains useful material but violates a frozen machine contract can still be unusable downstream.
  • Repair policy must be frozen. Decide before testing whether extraction, normalization, or retries are allowed and apply that rule equally.
  • Failed attempts need evidence. Preserve a non-sensitive hash, usage, latency, validation error, and disposition even when no quality score exists.
  • Attrition belongs in the denominator. Reporting only the five parseable pairs would hide the operational failure that prevented the sixth comparison.

What remains unknown

The committed evidence proves the contract violation; it does not prove why the model produced leading reasoning. The raw response is not public, and this single event cannot estimate a general failure rate. More frozen cases, independent reproductions, and equally applied retry policies are required before broader reliability claims.
